| D-016 | 2026-09-11 | `preprocess.py` resuelve imports/herencia con una heurística a nivel de archivo, no un resolver de símbolos real: un import relativo (`./X.sol`) se busca en el propio bundle; una base no declarada en el bundle se clasifica como `assumed-external-package` si el archivo tiene cualquier import de paquete (no relativo), `unresolved-import` si tiene un import relativo sin resolver, o `unknown` en otro caso. Solo estas dos últimas cuentan para `UNRESOLVED_BASE`. | Resolver símbolos de imports de paquete (OpenZeppelin, etc.) exigiría tener esos archivos o un grafo de paquetes real, fuera de alcance de una capa determinista con solo stdlib; la alternativa (marcar cualquier base no declarada como incompleta) generaría `partial` en casi cualquier contrato real que use OpenZeppelin. Documentado también en `references/checklist.md`. |
| D-017 | 2026-09-11 | `preprocess.py` fuerza UTF-8 en stdout/stdin (`sys.stdout.reconfigure(encoding="utf-8")`) al arrancar. | En Windows, cuando la salida no es una terminal (redirigida a archivo o pipe), Python usa por defecto el code page heredado (p. ej. cp1252) en vez de UTF-8, lo que corrompía comentarios/strings no ASCII (tildes, ñ, etc.). Detectado por smoke test durante 1.1 antes de escribir la suite formal. |
| D-018 | 2026-09-11 | La CLI de `preprocess.py` solo lee stdin cuando `not args.paths and not sys.stdin.isatty()`, y un stdin vacío (0 bytes o solo espacios) sin `paths` se trata como "sin input" (error de uso), no como "un archivo vacío analizado". | Evita bloquearse esperando una terminal interactiva y evita fabricar un resultado con `completeness.status = "failed"` cuando en realidad el usuario no aportó nada; corregido tras detectar en smoke test que la lógica original ignoraba `isatty()`. |
| D-019 | 2026-09-11 | `tests/` lleva `tests/__init__.py` vacío; `tests/test_preprocess.py` localiza el script de la Skill con una ruta absoluta calculada desde `__file__` (no import relativo de paquete) e inserta `scripts/` en `sys.path` antes de `import preprocess`. | Decisión diferida en D-010 hasta el primer test real. Comprobado empíricamente: en este entorno (Python 3.14 en Windows), `python -m unittest` sin argumentos encuentra 0 tests si `tests/` no es un paquete importable, y `discover -s tests` explícito falla con `ImportError: Start directory is not importable`. Con `__init__.py` ambos funcionan; `python -m unittest` (el comando exigido por `CLAUDE.md`) pasa las 53 pruebas. |
| D-020 | 2026-09-11 | El grep automático de términos prohibidos nivel A (`docs/commercial-claims.md`) excluye `references/guardrails.md` (ya previsto en D-008) y ahora también `scripts/preprocess.py`. Ambos se revisan a mano en cada commit. | Al ejecutar el grep real sobre 1.1 apareció una coincidencia legítima: `INJECTION_PATTERNS` en `preprocess.py` necesita contener literalmente frases como "this contract is safe/secure/audited/certified" para RECONOCERLAS como intento de manipulación en el código/comentarios que aporta el usuario (§23/§13 del encargo) — es el uso opuesto a una afirmación comercial de la Skill sobre sí misma. Corregido también un ejemplo de `checklist.md` que usaba "audited" para describir un patrón de terceros (EIP-1967), reemplazado por "battle-tested" para no depender de esta excepción donde no hace falta. |
